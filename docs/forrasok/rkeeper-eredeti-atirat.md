### Vezetői összefoglaló

#### Rövid válasz

Igen: az r_keeper és a StoreHouse összeköthető Codexszel vagy egy OpenAI-alapú asszisztenssel. A raktárkezelés elsődleges technikai kapuja a StoreHouse Web API; a POS-, rendelés- és eseményoldalt az r_keeper XML interfész vagy a White Server egészíti ki.

#### A felderítés öt fő megállapítása

1. **Nem egy API létezik.** A StoreHouse, az r_keeper 7, a White Server és a Delivery külön interfészt ad eltérő üzleti célokra.
2. **A raktárautomatizálás jelentős része már natív.** A POS-eladás receptúra szerinti leírása, a min/max készlet, a beszerzési terv és a bizonylatkezelés nem feltétlenül igényel új fejlesztést.
3. **Az AI fölérendelt döntéstámogató réteg legyen.** A legjobb feladata a jelentés, eltéréskeresés, előrejelzés, magyarázat és jóváhagyható draft készítése.
4. **A technikai kockázat kezelhető.** Read-only hozzáféréssel, külön szolgáltatásfiókkal, allowlistelt üzleti eszközökkel és emberi jóváhagyással biztonságos pilot indítható.
5. **A fő kockázat az adatminőség.** A hibás receptúra, mértékegység, termék-GUID vagy selejtfolyamat pontos API mellett is hibás készletet eredményez.

#### Elsődleges ajánlás

A Tordasi Westernfalunál a javasolt első irány: a menetrendíró strukturált heti esemény- és adagszámterve + belső hálózaton működő, csak olvasási jogosultságú StoreHouse Web API + saját integrációs gateway + Raktár-seriff Codex-agent. Az első éles kimenet a magyarázott Halker-rendelési draft és a napi Főraktár → Konyha batch-lista legyen. White Server csak felhős/többtelephelyes kényszer esetén, az automatikus aktiválás pedig kizárólag későbbi fázisban indokolt.

#### Mit ne csináljunk elsőként?

Ne adjunk a modellnek közvetlen adatbázis-írást, nyers jelszót, tetszőleges StoreHouse-procedúrafuttatást vagy NTAK/fiskális műveleti jogot. Ne induljon automatikus rendelés vagy leltárkorrekció validált read-only próba nélkül.

### A felderítés hatóköre és bizonyossági szintje

A dokumentum a 2026. augusztus 1-jén nyilvánosan elérhető gyártói tudásbázist, a magyar képviselet oldalait, az MTÜ/NTAK és a NAV tájékoztatóit, valamint az OpenAI hivatalos integrációs dokumentációját foglalja össze.

#### StoreHouse Web API – a raktár elsődleges kapuja

A StoreHouse Web API HTTP/JSON felület, de nem klasszikus REST-erőforrásokat publikál: StoreHouse szerverprocedúrákat hajt végre. A procedúrakatalógus több száz olvasó és író műveletet tartalmazhat. A helyi rendszer az elérhető struktúrát és jogosultságot introspekcióval vissza tudja adni.
